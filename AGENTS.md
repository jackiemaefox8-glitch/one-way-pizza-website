# Agent Rules — One Way Pizza

1. Inspect the repository and assets before changing files.
2. Follow the planning → implementation → test → audit → fix → re-verify workflow.
3. Treat `CLIENT_BRIEF.md` as supplied research, not proof of live verification.
4. Never invent prices, offers, testimonials, social URLs, current opening status or business claims.
5. Preserve the supplied logo and its proportions.
6. Keep the visual system restrained: black, gold and white, with minimal green.
7. Prefer simple, maintainable solutions over unnecessary infrastructure.
8. Do not add checkout, payment processing, authentication, database or admin dashboard unless explicitly required.
9. Do not claim a form works unless its submission path is implemented and tested.
10. Do not expose secrets or add private keys/tokens to frontend code.
11. Do not deploy, purchase a domain, contact the owner or perform irreversible external actions without explicit approval.
12. Report tests only as passed when they were actually run.
13. When a dependency, asset, fact or configuration is missing, state the gap instead of guessing.
