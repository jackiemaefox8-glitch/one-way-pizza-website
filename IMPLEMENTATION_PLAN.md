# Implementation Plan — One Way Pizza

## Phase 1: Inspect and plan
- Inspect repository, assets, framework, package scripts and dependencies.
- Read this pack and inspect the supplied logo/brand board.
- Confirm the proposed section structure and implementation approach.
- Keep planning files updated if repository realities require changes.

## Phase 2: Foundation
- Set design tokens and responsive container/spacing rules.
- Add global typography and accessible base styles.
- Create header, navigation, buttons and footer.
- Centralise business information and external links.

## Phase 3: Main content
- Build hero and primary CTAs.
- Build featured menu and provisional deals.
- Build gallery and ordering steps.
- Build location, contact, provisional hours and footer.

## Phase 4: Interactions
- Verify Foodpanda, phone and Maps actions.
- Implement accessible mobile navigation.
- Implement a contact form only with honest submission behaviour.
- Add WhatsApp only if supported/approved by the owner.

## Phase 5: QA
- Run build, lint, type checks and available tests.
- Test links, form states and mobile navigation.
- Review multiple viewport widths.
- Check accessibility, SEO, image loading and console/network errors where possible.
- Fix issues and re-run relevant checks.

## Phase 6: Handover
- Update README with setup and run instructions.
- Provide a test report.
- List outstanding client confirmations and demo limitations.
- Do not deploy without explicit approval.
